# 启动台

一款用 Swift、SwiftUI 和 AppKit 编写的原生 Mac 应用，重现 macOS 15 启动台的全屏应用网格、模糊桌面背景、搜索、分页和文件夹。读取本机的应用名称与图标，点击即可启动真实应用。

## 构建与运行

需要 macOS 14 或更新版本以及 Xcode Command Line Tools（`xcode-select --install`）。不依赖第三方库，不需要 Xcode 工程。

```sh
./Scripts/build.sh
open "build/启动台.app"
```

生成的应用位于 `build/启动台.app`，可双击运行，也可自行将它移到“应用程序”文件夹。构建脚本只在项目内写入产物，不修改系统启动台或 Dock。应用使用本机临时签名；将它分发给其他 Mac 时，需要另行完成开发者签名及公证。Apple Silicon 与 Intel Mac 均可从源码编译，默认生成当前构建电脑架构的应用。

也可以用 `open Package.swift` 在 Xcode 中打开源码。

## 使用

- **打开或收起**：按 `⌥⌘L`（Option–Command–L），或点击应用图标。全局快捷键在应用运行期间可用。
- **搜索**：直接输入应用名称；支持中文、英文和拼音。按 `Return` 启动选中的应用。
- **选择与分页**：方向键选择应用；点击下方圆点、横向滚动，或按 `⌘←` / `⌘→` 翻页。
- **退出当前界面**：按 `Esc`，先返回上一级或清除搜索，再收起启动台。
- **整理**：拖到图标的左侧或右侧调整位置；拖到图标中央建立文件夹，拖到文件夹上加入。拖至屏幕边缘可跨页移动。
- **文件夹**：点击打开；点击文件夹名称重命名；拖动成员可以排序，拖到面板外或使用右键菜单可移出。
- **退出程序**：按 `⌘Q`。收起启动台后，应用仍保持运行，以便使用全局快捷键。

应用将网格与文件夹布局保存在 `~/Library/Application Support/com.local.ClassicLaunchpad/layout.json`。这里只整理启动入口，不会卸载或删除实际应用。

## 应用目录与边界

从本机常用应用目录读取 `.app` 软件包；使用系统提供的应用图标与名称。应用可能因磁盘未挂载、目录位置特殊、权限限制或软件安装方式而未出现在列表中。系统内部服务和嵌套辅助程序不会作为普通应用全部展示。

界面采用经典启动台布局，图标取自当前系统，因此在 macOS 26 上会显示当前版本的应用图标。壁纸为系统提供的桌面静态图像；动态壁纸不可用时显示内置渐变背景。界面打开期间菜单栏和 Dock 自动隐藏，移到屏幕边缘可显示；收起后恢复原来的显示行为。

这是独立实现的启动器，使用公开 macOS API，不导入或修改苹果系统启动台的私有数据库。桌面背景效果与屏幕设置、壁纸类型和系统减少透明度选项有关。

## 验证与图标

```sh
./Scripts/test.sh
```

测试脚本先构建，然后执行 `--smoke-test`。测试通过 `CLASSIC_LAUNCHPAD_DATA_DIR` 使用独立临时目录，结束后清理该目录。

应用图标的可编辑矢量源文件为 `Scripts/MakeIcon.swift`；运行 `./Scripts/make-icon.sh` 可以重新生成 `Resources/AppIcon.icns`。

需要验证真实鼠标拖放时，运行 `./Scripts/prepare-ui-test.sh`，再打开 `build/启动台测试.app`。它使用独立测试布局、普通窗口和拖放日志，不会改动正式应用的布局；测试产物均位于 Git 忽略的 `build/` 中。

GitHub Actions 会在 macOS 15 的 Apple Silicon 和 Intel 环境构建、测试并生成应用 ZIP。推送到 `main`、`codex/` 分支或提交 Pull Request 后自动运行。

- 原生拖放结束或取消时清理状态，防止误启动应用；保持网格和图标视图稳定。
